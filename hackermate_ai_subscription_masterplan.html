Slide 11 / 22 — Legal: Entity & Incorporation

Business Entity & Incorporation

Required legal structure to collect payments, issue invoices, and operate as a SaaS business in India.

🏛️ Recommended: Private Limited Company

  • Structure: Indian Private Limited Company (Pvt. Ltd.) under Companies Act, 2013
  • Why: Limited liability, ease of fundraising (equity issuance), credibility with B2B organizers and partner hackathons
  • Registration: MCA (Ministry of Corporate Affairs) via SPICe+ form
  • Min Directors: 2 (at least 1 Indian resident)
  • DIN & DSC: Director Identification Number + Digital Signature Certificate required
  • Timeline: 10-15 business days for incorporation
  • Cost: ₹8,000 – ₹15,000 (including govt fees + professional charges)

📋 Post-Incorporation Checklist

  • PAN & TAN: Apply immediately post-incorporation (auto-generated via SPICe+)
  • GST Registration: Mandatory once turnover exceeds ₹20L (or immediately if selling SaaS nationally online)
  • Current Account: Open a business bank account (required for Razorpay/Stripe KYC)
  • Startup India Registration: Optional but recommended — tax benefits under Section 80-IAC (3-year tax holiday)
  • MSME/Udyam Registration: Free, provides access to government tenders and SIH organizer credibility
  • Trademark Filing: File "HackerMate" trademark (Class 42 — SaaS, Class 9 — Software) via IP India
💡

Alternative: LLP (Lower Compliance Burden)

A Limited Liability Partnership is viable for early stage (lower compliance costs, no board meeting requirements). However, it's harder to raise VC funding and issue ESOPs. Recommended only if bootstrapping indefinitely.

Slide 12 / 22 — Legal: Data Privacy

Data Protection & DPDP Act 2023

India's Digital Personal Data Protection Act, 2023 governs how HackerMate collects, processes, and stores user data.

📜

DPDP Act 2023 — Key Obligations

  • Lawful Purpose & Consent: Obtain explicit, informed consent before collecting personal data (name, email, skills, GitHub). Display clear consent notice at onboarding.
  • Purpose Limitation: Data collected for matchmaking & collaboration must not be repurposed for unrelated advertising without fresh consent.
  • Data Minimization: Collect only what is necessary. Avoid collecting Aadhaar, financial data, or sensitive biometrics.
  • Right to Erasure: Users can request complete account deletion. Current RPC delete_user_procedure already supports this — extend to AI embeddings and logs.
  • Data Fiduciary Obligations: HackerMate is a "Data Fiduciary" — must appoint a Grievance Officer with contact details on the platform.
  • Children's Data: If users are under 18, parental consent is required. Add age verification during onboarding.
🌍

Cross-Border & International Compliance

  • Data Localization: DPDP Act does not mandate data localization (unlike RBI data). Supabase hosting on AWS Mumbai (ap-south-1) is recommended but not legally required.
  • GDPR Awareness: If EU users sign up, minimal GDPR provisions apply — add cookie consent banner and data processing addendum.
  • Third-Party LLM Data: When sending user data to Gemini/OpenAI APIs, ensure a Data Processing Agreement (DPA) is signed. Use "no-training" opt-out flags.
  • Payment Data: HackerMate never handles raw card data — Razorpay/Stripe handle PCI-DSS compliance. Store only gateway customer IDs and subscription references.
  • Breach Notification: DPDP requires notifying the Data Protection Board and affected users in case of a breach. Build an incident response playbook.
🚨

Action Required: Privacy Policy & Terms of Service

Draft and publish Privacy Policy, Terms of Service, Refund & Cancellation Policy, and AI Usage Disclaimer before accepting any payments. These must be linked from the pricing page and checkout flow. Consult a tech lawyer for final review.

Slide 14 / 22 — Legal: IP & AI Ethics

Intellectual Property, Licensing & AI Ethics

🔐 Intellectual Property

  • Trademark: File "HackerMate" word mark + logo under Class 9 (Software) and Class 42 (SaaS) with IP India. Cost: ~₹4,500/class. Timeline: 18-24 months for registration, but TM™ protection starts from filing date.
  • Copyright: Source code is automatically copyrighted under Indian Copyright Act, 1957. No registration needed, but registration strengthens enforcement.
  • Open Source Licenses: Current dependencies (Next.js — MIT, Supabase — Apache 2.0, React — MIT) are permissive. No copyleft risk. When adding LLM SDK (Google AI SDK — Apache 2.0), verify license compatibility.
  • User-Generated Content: Terms of Service must clarify that user-uploaded content (project ideas, pitches, code) remains user IP. HackerMate gets a limited license to process and display — not to resell or train models on.
  • AI-Generated Output Ownership: Explicitly state in ToS that AI-generated content (PPT drafts, task breakdowns) is provided as-is with no IP warranties. Users own their final submissions but HackerMate disclaims AI output accuracy.

🤖 Responsible AI & Ethics Policy

  • Transparency: Clearly label all AI-generated content with "Generated by HackerMate AI" badges. Never present AI output as human-verified.
  • No Autonomous Submissions: AI drafts are always presented as suggestions requiring human review. Never auto-submit to hackathon portals without user confirmation.
  • Bias Mitigation: Regularly audit matchmaking algorithms for bias (gender, college tier, region). Publish diversity metrics quarterly.
  • Prompt Injection Defense: Existing safety.ts content filters extended to AI prompts. Block attempts to extract system prompts, generate harmful content, or manipulate scoring.
  • Data Not Used for Training: Explicitly commit that user workspace data is NEVER used to train or fine-tune any LLM. Use API providers' no-training agreements (Gemini API ToS, OpenAI API ToS both support this).
  • IT Act 2000 (Section 43A): Mandates "reasonable security practices" for handling sensitive personal data. Our existing RLS, encryption at rest (Supabase), and HTTPS satisfy this.

Slide 18 / 22 — Security & Quota Management

Security Hardening & Quota Enforcement

🛡️

Payment Security

  • HMAC Webhook Verification: All Razorpay/Stripe webhooks verify cryptographic signatures before database writes
  • Idempotency Keys: Prevent duplicate subscription activations from webhook retries
  • No Raw Card Data: PCI-DSS handled entirely by payment gateways — HackerMate stores only gateway reference IDs
  • Subscription State Machine: PostgreSQL enum enforces valid state transitions (trialing → active → past_due → cancelled)
⚡

AI Quota & Abuse Prevention

  • Atomic Credit RPC: check_and_deduct_ai_credit() — transactional PostgreSQL function prevents race conditions and double-spending
  • Token Clamping: System prompts set strict max_output_tokens per feature (1024 for tasks, 2048 for PPTs)
  • Rate Limiting: Extends existing rate_limits table — max 10 AI calls/minute per user, 30/minute per team
  • Prompt Injection: Input sanitized via safety.ts content filters + Gemini's built-in safety settings
  • Default-Deny UX: Exhausted credits show clean upgrade modal — no raw API errors leak to users
✅

Existing Security Foundation

HackerMate already has 111 database migrations with comprehensive RLS policies, advisory locks, HMAC-signed invite tokens, content safety filters, and rate limiting. The AI/billing layer builds on this battle-tested foundation.
