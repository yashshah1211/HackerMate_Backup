# PPT document identity and score consistency

The reported 12/100 and 35/100 evaluations used the same URL, page count, byte count, mode and model. Those facts do not establish that the downloaded PDF bytes were identical; the URL may return changed content and no fingerprint was recorded. The observed six-page PDF also does not establish that either evaluation used the intended ten-slide deck. Without the two original PDFs, full inputs and model responses, the cause of the difference cannot be established.

The native-PDF scorer makes one generative-model request with temperature 0.1 and a selected rubric. Low temperature is not a deterministic scoring guarantee. The prompt also includes title, category, track, custom rubric, extracted text and team skills, so identical bytes alone would not prove identical inputs. The server validates category caps, arithmetic, deductions and page references; for visual evidence it checks a page number and nonempty description, not whether the described pixels or claims are true. The prompt now explicitly calls self-reported performance, adoption and impact claims rather than verified results; this instruction cannot guarantee model compliance. Mockups and unverified claims are not independently validated. The 12-versus-35 difference is not evidence of a heuristic fallback, and no heuristic fallback was introduced.

Successful evaluations now store a SHA-256 digest of the downloaded PDF bytes in existing analysis metadata, including when a failed PDF request falls back to text. The digest identifies the downloaded input, not independent validation of model reasoning, document authorship or historical provenance. Text-only extractions without PDF bytes and older records have no PDF fingerprint; neither URLs nor lengths are used as substitutes. Same-team earlier completed evaluations with the same valid recorded hash are identified in the UI, without changing scores, version history or the ability to request another review. Existing records remain marked as historically unverified.

Offline tests use generated PDFs and synthetic provider responses. They exercise extraction, score contracts, modes, failure handling, hash persistence and repeat matching. Controlled strong/weak mock responses demonstrate contract arithmetic only: they cannot establish that the real model ranks the fixtures correctly or that repeated live scores are consistent. Those questions require separately authorized paid model evaluation; no live provider requests were made for this change.
